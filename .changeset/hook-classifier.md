The hook now classifies what the deterministic engine cannot approve itself, synchronously, with the harness's own logged-in CLI (`claude -p`, `codex exec`, `copilot -p`; no tools, no hooks, no session persistence). It approves when the answer is recoverable with confidence 0.95 or more and a category other than sensitive or unknown. Hard human items (credentials, protected configuration, unrecoverable loss, humanPatterns) never reach the classifier. Everything else asks the person and waits: Claude Code and Copilot ask in their own prompt, and a "yes" (seen in PostToolUse) is remembered for the session with the `approve --session` scope; Codex keeps the deny with `pm approve --last`. The user's own Claude Code permission rules and Codex execpolicy rules are honored: a deny or ask rule leaves the request to the harness, and an allow rule counts as the person's answer. The old "block and ask the agent to classify" flow is gone; the `classify` command still works. New profile key `classifier` (per-CLI `model`, `enabled: false`). Every managed hook now has a 45-second timeout. `replay --classify` runs the real classifier on recorded escalations. The hard list reads commands the way the shell runs them (quotes, `eval`, `sh -c`, `$(…)`, wrappers, `cd`, Git aliases) and covers more harness settings files.
